# 04 文件操作：写进去，再读回来

## 题目

把 5 个学生（姓名、成绩）写进 `students.txt`，再重新打开读回来打印，要求跟原来一致。

```
1. struct student { char name[20]; int score; };
2. 准备 5 个学生（键盘录入）
3. fopen(..., "w")，fprintf 每行写一个：名字 空格 分数
4. fclose
5. 重新 fopen(..., "r")，fscanf 读回数组
6. 打印，跟原来一致
```

## 涉及的知识点

- `fopen(文件名, 模式)` 返回 `FILE *`（"门把手"），失败返回 `NULL`
- 三种模式：`"w"` 自动创建 / 存在就清空；`"r"` 不存在返回 `NULL`；`"a"` 追加
- **`fprintf` / `fscanf` 就是换了对象的 `printf` / `scanf`**：

  | 屏幕 | 文件 |
  |---|---|
  | `printf("...")` | `fprintf(fp, "...")` |
  | `scanf("...", &x)` | `fscanf(fp, "...", &x)` |

- **`&` 的规矩**：数组名本身就是指针（`list[k].name` 不用 `&`），普通变量必须取地址（`&list[k].score`）
- **`fscanf` 的返回值 = 成功读到的数据项个数**，格式串里有两个 `%` 就要返回 2
- **缓冲区**：`fprintf` 写的内容先存在内存里，`fclose` 才真正刷到磁盘，所以 `fclose` 不能省
- 一个 `fopen` 配一个 `fclose`，同一个指针不能关两次

## 踩过的坑

1. **`scanf("%s %d", list[k].name, list[k].score)`** —— 漏了 `&`。`%d` 要的是地址，
   gcc 直接报警：`format '%d' expects argument of type 'int *', but argument 3 has type 'int'`
2. **从头到尾没有 `printf`** —— 程序跑完一声不吭，于是误以为"出错了"，其实是输出漏了
3. **`fp2` 没判 `NULL`** —— 第一次判了，第二次忘了
4. **`fscanf` 返回值没判** —— 读失败也不知道
5. **循环里留了两句 `fscanf`** —— 每次读两条只留一条，5 条记录喂进去，第三次循环就报"第 3 个读取失败"。症状本身就指向了病因

## 编译与测试

```bash
gcc -Wall -Wextra -o student_file student_file.c
```

`-Wall -Wextra` 零警告。喂 5 个学生测试：

```
输入：张三 88 / 李四 92 / 王五 75 / 赵六 60 / 钱七 100
输出：完全一致，5 条，无遗漏
```

## 判据（这道题的验收标准）

| # | 判据 | 结果 |
|---|---|---|
| 1 | 两个 `fopen` 都判了 `NULL` | ✓ |
| 2 | 文件里恰好 5 行，格式 `名字 分数` | ✓ |
| 3 | `fscanf` 的返回值判了 | ✓ |
| 4 | 两个 `fclose` 都在 | ✓ |

## 一句话总结

**写进去的格式和读回来的格式必须对得上** —— 这就是文件操作的命门。
