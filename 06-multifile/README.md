# 06 多文件编译：拆成 .h + 多个 .c

## 题目

把 05 那个单文件程序拆成真实项目的样子，三个文件各司其职：

```
student.h   ← 结构体定义 + 四个函数的「声明」
student.c   ← 四个函数的「定义」（真正干活的代码）
main.c      ← 只管调用，不写实现
```

要求：

```
1. student.h 要有头文件保护（#ifndef / #define / #endif）
2. student.h 里只放声明，不放实现
3. main.c 用 #include "student.h"（双引号，不是尖括号）
4. 编译时两个 .c 必须一起交给 gcc
5. 零警告
```

## 涉及的知识点

- **声明（declaration）vs 定义（definition）**
  `void input(struct student *a, int n);` 结尾有分号，这是声明——只告诉编译器「有这么个函数，长这样」。
  去掉分号换成 `{ ... }` 才是定义——真正分配了代码。
  **头文件里放声明，.c 里放定义。** 这是整套东西的地基。

- **编译单元（translation unit）**
  每个 `.c` 文件是独立编译的，编译器一次只看一个 `.c`。它编译 `main.c` 时根本不知道 `student.c` 长什么样，只能信 `student.h` 里的声明。

- **链接（linking）**
  编译完各得到 `.o`（目标文件），链接器把它们拼成一个 `exe`。
  如果某个函数只有声明、所有 `.o` 里都找不到定义，链接器就报
  `undefined reference to 'xxx'` —— **这是链接错误，不是语法错误。**

- **`#include "..."` 和 `<...>` 的区别**
  双引号：先搜当前源文件所在目录，再搜系统目录。自己写的头文件用双引号。
  尖括号：只搜系统目录和 `-I` 指定的路径。

- **头文件保护**
  防止同一个 `.h` 在一次编译里被 `#include` 两次（间接重复包含），导致结构体被定义两遍。

- **头文件里不要定义变量**
  只放声明和类型。否则每个 include 它的 `.c` 都会得到一份同名的全局变量定义，链接时冲突。

## 核心结构

```
        student.h
        ┌──────────────────────┐
        │ struct student       │
        │ input / save / load  │  ← 只有声明
        │ print                │
        └──────────┬───────────┘
                   │ #include
        ┌──────────┴───────────┐
        │                      │
     main.c                student.c
   （调用这四个函数）      （实现这四个函数）
        │                      │
        └──────┬───────────────┘
               │  gcc main.c student.c -o prog
         main.o + student.o
               │  链接
             prog.exe
```

`main.c` 里没有一行实现，`student.c` 里没有一行 `main`。**职责分开，就是多文件的意义。**

## 踩过的坑

1. **Dev-C++ 里按编译/运行，报一堆 `undefined reference`**
   因为 Dev-C++ 默认**只编译当前打开的那个文件**。只编 `main.c` 时，`input`/`save`/`load`/`print` 全都只有声明没有定义，链接器当然找不到。
   解决：建工程把两个 `.c` 都挂进去，或者命令行 `gcc main.c student.c -o prog`。

2. **Dev-C++ 新建工程 → 向导里「文件」框填了 `main.c`**
   那个框是让你给**新建的源文件**起名，不是指认已有文件。填了已存在的名字会报「文件已经存在于 xxx.dev」。
   正确做法：向导里取消/跳过新建文件，工程建好后右键工程 → 添加 → 把已有的 `.c` 挂进去。

3. **忘记头文件保护**
   要是哪天 `student.h` 被两个头文件间接包含，结构体会被定义两次，报 `redefinition of 'struct student'`。

## 编译与测试

```bash
gcc -Wall -Wextra main.c student.c -o prog
```

`-Wall -Wextra` 零警告。

实测跑通：输入 2 个学生（`大大 35`、`电视广告 435`），写入 `students.txt` 再读回，打印结果一致。

## 判据（验收标准）

| # | 判据 | 结果 |
|---|---|---|
| 1 | 三个文件拆开，`.h` 只有声明 | ✅ |
| 2 | `student.h` 有 `#ifndef` 头文件保护 | ✅ |
| 3 | `main.c` 用双引号 include | ✅ |
| 4 | 两个 `.c` 一起编译，零警告 | ✅ |
| 5 | 单独编 `main.c` 会报链接错误（证明拆得是真的） | ✅ |

第 5 条是这道题的关键验证：**如果单独编 `main.c` 也能过，说明你其实没拆，只是复制了一份代码。**

## 一句话总结

**编译错误是「这句写错了」，链接错误是「这个符号没人实现」。**
分清这两类报错，以后一个人写十几个文件也不会慌。
